# Moryń — 3D Digital Twin

A Three.js + Vite model of the municipality of Moryń (Poland): a 5.64 × 5.64 km
16-bit heightmap terrain with OpenStreetMap buildings, roads and water
(Jezioro Morzycko) on top.

## Run locally

Requires Node 18+.

```bash
npm install
npm run dev          # http://localhost:5173
```

Production build:

```bash
npm run build        # outputs dist/
npm run preview      # serves dist/ on http://localhost:4173
```

`public/data/` already holds the heightmap and a snapshot of OSM data.

The web heightmap is generated from the original `moryn.png` (4033², 19.6 MB),
downsampled to 1025² lossless 16-bit (1.47 MB): one pixel per vertex of the
`segments: 1024` terrain mesh (~5.5 m cells).

```bash
npm run heightmap    # moryn.png → public/data/heightmap.png (1025²)
# Lighter option for segments: 512 (0.39 MB; at that mesh density it gives
# exactly the same terrain as the full original):
node scripts/downsample-heightmap.mjs moryn.png public/data/heightmap.png --size 513
```

Keep `--size` equal to `terrain.segments + 1` in `src/config.js`.

To refresh the OSM layers:

```bash
npm run fetch-osm    # Overpass API → public/data/{buildings,roads,water}.geojson
# Use another Overpass mirror if the main one is busy:
OVERPASS_URL=https://overpass.kumi.systems/api/interpreter npm run fetch-osm
```

## How it works

### Georeferencing
The scene frame is metric: **+x = east, +z = south, y = metres a.s.l.**, with the
origin at the centre of the heightmap. GeoJSON lon/lat is projected with proj4
into the heightmap's own CRS, then offset by the DEM centre.

The heightmap had no embedded georeference. I recovered its CRS and centre by
matching the DEM's flat lake surface against the OSM outline of Jezioro Morzycko:

| CRS | Lake overlap (IoU) |
| --- | --- |
| EPSG:2180 (PUWG-1992, the GUGiK grid) | **0.92** |
| EPSG:32633 (UTM 33N) | 0.85 |
| EPSG:3857 (Web Mercator) | scale mismatch, rejected |

The resulting centre (E 189 892, N 565 427, EPSG:2180) is in `src/config.js`.
If you have the DEM's real metadata (e.g. a `.tfw`/`.aux.xml`), put the exact values there.

### Terrain
- The PNG is decoded with `fast-png` in a Web Worker. A canvas decode would drop
  it to 8 bits, which turns 66 m of relief into 26 cm steps.
- The heightmap is box-filtered onto a 1025² vertex grid (~5.5 m cells) and
  mapped linearly onto 30–96 m. The shipped 1025² file maps one pixel to each vertex.
- **CPU displacement** was chosen over a GPU displacement map on purpose:
  `Terrain.heightAt()` interpolates over the *same triangle split* that
  `PlaneGeometry` uses. Buildings, roads and water are therefore placed on
  exactly the surface the GPU draws, not on a separately sampled DEM.
- Vertex colours come from elevation and slope. A shader patch adds contour lines.
- `verticalExaggeration` in the config makes the gentle relief easier to read.

### Buildings
- Footprints, including holes and multipolygon relations, are extruded with `ExtrudeGeometry`.
- Height comes from the `height` tag, then `building:levels × 3 m`, then a per-type default.
- Walls start 1.5 m below the lowest ground point under the footprint, so no gap shows on slopes.
- All buildings are merged into a single draw call. A triangle-range table maps
  raycast hits back to OSM features for the info panel and highlighting.

### Roads
- Lines are densified to half a terrain cell, then expanded into mitred ribbons.
  Each edge samples the terrain separately, so roads tilt with cross-slopes.
- Z-fighting is avoided with a 0.35 m lift, a small per-class height step (major
  roads win at junctions) and `polygonOffset`.

### Lighting
- Physical `Sky` (with slow-moving clouds), a PMREM environment map built from
  the same sky, a hemisphere fill light and `FogExp2`.
- The sun's shadow frustum follows the orbit target and scales with zoom. It is
  snapped to shadow-map texels so shadows don't shimmer while panning, which
  keeps house shadows sharp close up without a huge shadow map.

### Wind turbines
`public/data/turbines.geojson` holds 48 turbines digitised from the planning
map `wiatraki.jpg`:

| Map symbol | Status | Count | Tip height |
| --- | --- | --- | --- |
| red circle | planned | 25 | 280 m (185 m hub + 95 m blades) |
| purple circle | planned | 11 | 210 m |
| black circle (Wierzchlas/Kamionka) | existing | 12 | 150 m (100 m hub + 50 m blades, per the map legend) |

How the positions were digitised:
- The map is drawn on the PUWG 2000 zone 5 grid (EPSG:2177). It was calibrated
  on its grid ticks: 5 452 000 / 5 456 000 E and 5 864 000…5 856 000 N, giving
  ~12.7 m per pixel, which agrees with the map's scale bar.
- The calibration was checked by overlaying the OSM outline of Jezioro Morzycko,
  which lands on the lake drawn on the map.
- Dot centres were found automatically (filled red cores, sub-pixel centroids).
  Each dot's height comes from the colour of the 1000 m circle around it.
- Black circles were found as hollow ~14 px rings. Letters of the village names
  that look like rings were excluded.
- OSM also maps exactly 12 wind generators (2.5 MW) in the Wierzchlas/Kamionka
  area, which matches the count.
- Expect position errors of roughly ±15–25 m from the map's resolution.

Each turbine is a clone of the glTF model, scaled to its tip height. All rotors
face WSW (into the prevailing wind) and turn at about 8 rpm, each with a random
phase and ±10% speed. The model and its settings are in `windTurbines` in
`src/config.js`.

### Surroundings
Only 1 of the 48 turbines falls on the 5.64 km heightmap, so
`src/terrain/surroundings.js` adds ground beyond it:
- A ring of terrain starts on the terrain's edge vertices, with the same heights,
  colours and normals, so there is no seam.
- Over 1.5 km it blends into a flat plain at the mean edge elevation, which
  extends 40 km out, into the fog.
- The edge profile is smoothed along the perimeter more and more with distance,
  so edge details don't streak outward.
- Outside the DEM there is **no real relief**. A larger heightmap of the whole
  municipality would make the outer turbines' bases exact.
- The camera can pan up to 7.5 km past the terrain edge to reach the outer turbines.
- Set `surroundings.enabled: false` to bring back the diorama look.
